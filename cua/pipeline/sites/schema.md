# Site registry schema

Every `public_sites*.json` in this directory is one capture lane's worklist. They share one shape,
so adding a lane or a site is a data edit, never a new loader: `cua/pipeline/sites/registry.py`
(`load_sites`, `find_site`, `resolve_named_sites`, `known_site_configs`) reads all of them, and
`--sites <name>` resolves across every file matching `SITE_CONFIG_GLOB` (`public_sites*.json`).

```json
{
  "_comment": "why this file exists and how it was curated",
  "sites": [
    {
      "name": "example",
      "start_url": "https://example.test/app",
      "domain": "productivity",
      "category": "notes",
      "provisioning": "email_verify",
      "tasks": [
        {
          "id": "create-note",
          "instruction": "Write a note titled 'Groceries' and save it.",
          "difficulty": "medium",
          "expected_actions": 8,
          "action_kinds": ["click", "type"],
          "auth_required": true
        }
      ]
    }
  ]
}
```

## Top-level keys

| key | meaning |
| --- | --- |
| `sites` | the only key any loader reads: the list of site objects |
| `_comment` | free prose about the file's purpose and curation policy |
| `_README` | the file's own operator documentation, used by the guarded lane's template |
| `_task_design` | how the tasks in this file were designed |
| `_task_order` | why the tasks run in the order they are listed |
| `_feature_verification` | what the lane must re-check after acting, for `qa_verify`-style files |
| `_recipient_address` | the burner address any task in this file may send to |
| `_config` | per-file capture hints kept with the data rather than in code |
| `_excluded_<name>` | why a candidate site was deliberately left out, kept so it is not re-added |

Any key starting with `_` is documentation. Loaders ignore it, so a new one needs no code change.

## Site keys

| key | required | used by | meaning |
| --- | --- | --- | --- |
| `name` | yes | every lane | the slug; the capture lands in `trajectories/site_<name>/` and `--sites` matches it |
| `start_url` | yes | every lane | where every task for this site starts; also matchable by `find_site` |
| `domain` | yes in practice | `capture_lane.verify_and_finalize` | the corpus `metadata.domain`; defaults to `public_web` when absent |
| `tasks` | yes | every lane | the task list (may be `[]` when the proposer fills it in — see below) |
| `category` | no | proposer grounding | a short topic label, used as the proposer's repo description when `domain` is absent |
| `provisioning` | login-gated lanes | `logingated`, `probe_capturable` | how an account is obtained: `open_signup`, `email_verify`, `phone`, `invite`, `paid`, ... The autonomous lane attempts only `open_signup` / `email_verify` |
| `skip_capture` | no | `public`, `probe_sandbox` | `true` drops the site from `load_sites`; `--sites <name>` still runs it, so a dud can be re-probed |
| `skip_reason` | with `skip_capture` | operators | why it was skipped; `probe_sandbox --mark` writes both |
| `task_style` | no | proposer, teacher, verifier | a `TEACHER_STYLE_BLOCKS` / `VERIFY_STYLE_RULES` key, e.g. `search`, `qa_verify` |
| `autonomy` | no | `public` | `autonomous` (default) or `guarded` — guarded gets confirm/handoff and is never given secrets |
| `auth_mode` | no | `public` | `none` (default) or `pre_session` — start signed in from a saved session |
| `burner_account_id` | when auth is needed | `public` | id into `credentials/burner_accounts.json`; an unregistered id fails the site closed |
| `storage_state_ref` | with `pre_session` | `public` | name of `credentials/storage_state/<ref>.json`; a missing file fails the site closed |
| `note` | no | operators | curation prose about this one site |

`autonomy` / `auth_mode` / `burner_account_id` / `storage_state_ref` are what
`lanes/public._resolve_site_auth` reads, fail-closed: a site that needs auth without a vetted burner
(or without its saved session) is skipped before a sandbox starts, so a real login is never touched.
`public_sites_human.json` is generated by `lanes/provision_human.py` and always carries all four.

## Task keys

| key | required | used by | meaning |
| --- | --- | --- | --- |
| `id` | yes | every lane | the task slug; the recording lands in `task_<safe_task_id(id)>/` |
| `instruction` | yes | teacher, verifier | a terse user GOAL, never a step-by-step procedure |
| `difficulty` | yes in practice | `metadata.difficulty`, login-gated task order | `easy`, `medium` or `hard`; the login-gated lane runs easy first |
| `expected_actions` | yes in practice | verifier efficiency, RL task filtering | the action budget a competent run should need |
| `action_kinds` | no | curation, RL suite balance | which action types the task should exercise |
| `auth_required` | no | curation, RL preconditions | whether the task needs a signed-in session |
| `requires_upload` | no | RL suite | excluded from RL: the sandbox has no file to upload |
| `idempotent` | no | RL suite | whether re-running the task leaves the site unchanged |
| `success_check` | no | RL reward | a `cua.rl.checks` registry key evaluated programmatically |
| `milestones` | no | RL reward, verifier | intermediate states a correct run passes through |
| `note` | no | operators | curation prose about this one task |

## Which lane needs which

- **`lanes/public`** (`public_sites*.json`, default `public_sites.json`): needs `name`, `start_url`,
  `tasks`. Honors `skip_capture`, `task_style` and the four auth keys. A site may ship `tasks: []`
  and let the proposer fill them in — but `--no-propose` against such a file captures nothing, so
  the lane warns and names the file.
- **`lanes/logingated`** (`public_sites_actions_logingated.json`): additionally needs `provisioning`
  and per-task `difficulty` / `expected_actions`. It mints its own burner, so the auth keys are absent.
- **`lanes/register_real_site`**: takes its site on the command line, not from a registry.
- **`lanes/provision_human`**: reads `SOURCE_CONFIGS` (indie + login-gated) and writes
  `public_sites_human.json` with `autonomy`, `auth_mode`, `burner_account_id`, `storage_state_ref`.
- **`lanes/probe_capturable`** filters by `provisioning`; **`lanes/probe_sandbox --mark`** writes
  `skip_capture` + `skip_reason`.
- **`cua.rl.tasks`** builds the RL suite from these same files, excluding every site and normalized
  instruction the SFT corpus already trained on.
